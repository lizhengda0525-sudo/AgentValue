# AgentValue 前端与低负担录入调研

日期：2026-10-04。对象：当前个人助手前端预览；使用者：个人工作、学习和生活安排。范围：下一版前端的功能入口、任务展示、快速新增、排期和执行小计。依据为本轮页面截图、浏览器观察、当前源码、产品官方资料和 GitHub 用户反馈。本轮没有修改产品页面。

## 结论

优先把“快速收集、安排时间、记录结果”做顺。当前已有多种视图，主要短板是很多操作仍需要进入完整表单；新增事项一次显示 10 个字段，实际只有标题必填，但界面没有把常用和偶尔使用的属性分开。小计入口也打开同一张长表，造成重复查找。

建议普通任务只输入标题即可保存；日历里的新增才带入选定时间；任务详细属性按需展开。展示上以任务列表与日历的联动为重点，补齐快捷改期、行内操作、筛选与批量安排。计时结果带入小计，未计时的补录使用“开始时间＋时长”，说明可以稍后补充。以上是设计建议，尚未实现，也没有测量实际节省时间。

## 1. 当前流程检查

本轮检查三步，没有提交新增任务或小计，也没有改动真实收藏库。截图保留本轮实际界面，不使用此前截图作为证据。

### 第 1 步：今天页面——结构清楚，操作入口分散

![第 1 步：今天页面](D:/Codex/AgentValue/artifacts/assistant-ux-research/01-today.png)

计划与实际分栏、分类颜色、重点任务和专注入口都有基础。默认 08:00—21:00 的小时轴占用较多高度，零散任务需要滚动查看。首页没有同时呈现收件箱中未排期的任务；用户选任务和排时间仍需往返。

建议保留小时轴，同时提供紧凑的“当天日程列表”；提供可展开的未排期清单，并可拖入日程。字体和淡色文字存在可见的阅读风险，短时间块中的长文本会截断。尚未测量对比度，也未验证屏幕阅读器。

### 第 2 步：新增事项——填写负担高

![第 2 步：新增事项](D:/Codex/AgentValue/artifacts/assistant-ux-research/02-create.png)

一次显示标题、分类、项目、状态、优先级、计划日期、截止日期、开始、结束、备注，共 10 个字段。仅标题必填，其他字段并非都必须填写；但平铺方式容易让人以为应当填写完整。

当前从“今天”新增会预填当天 13:00—13:30；它来自固定默认值，不代表用户选了这个时段。分类默认工作，也不能代表每项生活任务的实际分类。弹窗打开后焦点落在关闭按钮，用户还需点击标题才能输入。

建议改为标题输入＋少量可选属性按钮；状态默认待办、优先级默认普通，均无需新建时选择。只有从具体日历时段新增，才带入那个时段。标题输入自动获得焦点。

### 第 3 步：执行小计——需要绕过整张任务表

![第 3 步：滚动到执行小计区域](D:/Codex/AgentValue/artifacts/assistant-ux-research/03-execution.png)

点击“记录执行小计”后，仍先显示任务完整编辑表，小计在下方；截图记录的是滚动到小计区域后的状态。记录日期、实际开始、实际结束、说明均需提供。预填实际时间来自原计划，并非计时结果。

建议单独打开小计编辑器：有计时记录时显示可核对的时间段；补录时填开始与时长，结束时间计算出来。成果文字可保存为空并标记“待补充”，以后回顾时再写。仅有文字、没有实际时间的成果记录应作为备注保存，不进入时长统计。

本次重点检查入口和字段，没有验证提交失败恢复、长期保存、跨午夜、睡眠恢复或完整键盘流程；截图不能证明无障碍合规。

## 2. 参考产品的做法

下表将官方说明与针对 AgentValue 的建议分开。没有登录或试用商业产品；套餐、平台差异只按公开说明核查，不做性能或效率排名。

| 参考对象 | 本轮核查到的做法 | 建议借鉴 |
| --- | --- | --- |
| Todoist | 快速新增支持在标题中输入日期等信息；说明可另行展开；识别错的日期词可取消识别。[官方说明](https://www.todoist.com/help/todoist/features/use-task-quick-add-in-todoist-va4Lhpzz) | 一行录入，识别结果显示成可修改的标签；不要求用户学习命令语法 |
| Todoist 日历 | 点选日历时段打开快速新增并带入 30 分钟时长，可拖动任务边缘调整时长；该文档标明相关日历能力属于 Pro/Business。[官方说明](https://www.todoist.com/help/todoist/features/set-a-task-duration-L1kYkZv8d) | 带入用户点击的位置，以开始＋时长代替两个时间框 |
| TickTick | 官方更新记录介绍了任务与日历同屏、拖放排期、Agenda 时间线及按需添加说明。[官方更新记录](https://ticktick.com/public/changelog/en.html) | 任务与日历联动；紧凑日程和小时轴按需要切换 |
| Microsoft To Do | 可以从其他任务列表选事项加入 My Day；未完成项仍保留在任务列表中。[官方说明](https://support.microsoft.com/en-us/todo/my-day-and-suggestions) | “今天想做”不必等于“今天截止”，也不必先定具体几点 |
| Sunsama | 每日规划分为选任务、检查预计工作量、排序和可选日历排期；预计和实际时间可以分别设置，实际时间可来自计时器。[每日规划](https://help.sunsama.com/docs/usage-guides/daily-planning/)、[计划与实际](https://help.sunsama.com/docs/usage-guides/tasks/planned-and-actual-times/) | 收集与排期分开；计时直接连接实际记录，回顾沿用记录 |
| Linear | 支持模板预填属性；列表/看板可配置分组，卡片不必展示所有详细属性，可打开预览查看。[模板](https://linear.app/docs/issue-templates)、[看板](https://linear.app/docs/board-layout) | 快捷模板、紧凑任务行和按需详情；不引入个人场景用不上的团队字段 |

补充：Linear 提供草稿处理机制，可以减少中断填写造成的损失；具体暂存和持久草稿行为不同。AgentValue 可借鉴“中断后继续填写”，不用照搬其团队流程。[创建与草稿](https://linear.app/docs/creating-issues)

Sunsama 另有“未记实际时以计划时间计入实际”的可选设置。AgentValue 应继续明确区分计划和真实记录，减少填写的方式应是计时和带入上下文。[官方时间说明](https://help.sunsama.com/docs/usage-guides/tasks/planned-and-actual-times/)

## 3. GitHub 反馈提醒了哪些设计风险

- Super Productivity 的 [#10100](https://github.com/super-productivity/super-productivity/issues/10100) 于 2026-09-13 提出：手机上的常用 Schedule 入口藏在菜单中，每次都要多走一步。本轮公开页面显示 Open。对 AgentValue 的启示：高频入口直接可见，更多菜单只放低频操作。这是一名用户的反馈，不能代表普遍发生比例。
- [#4194](https://github.com/super-productivity/super-productivity/issues/4194) 是 2025 年关于快捷输入中日期和时长组合识别错误的报告，当前页面标记 Closed。它是历史案例，不代表当前版本仍有该缺陷。启示：自然语言解析必须显示明确的日期、时间和时长，支持纠正、取消；不能把解析能力当成无错误的自动化。

本轮也搜索了 Reddit 的自然日期识别及每日清单讨论，但检索到的多为旧的零散帖子，未用其推断当前故障或发生频率。没有 AgentValue 用户使用日志，因此优先级来自你的反馈、本轮可复核界面和高频个人使用场景。

“频率”列是场景触发频率，并非用户样本统计。高/中影响是产品判断；置信度区分事实与效果预测。

## 5. 把 10 个字段变成按需填写

| 当前字段 | 普通快速新增 | 何时补充 |
| --- | --- | --- |
| 标题 | 唯一需要输入的内容 | Enter 保存；输入框直接聚焦 |
| 分类 | 可不选，默认未分类；从分类入口新增可带入该分类 | 点击工作/学习/生活标签 |
| 项目 | 无需填，可从项目入口带入 | 从已有项目列表选择，避免重复打字 |
| 状态 | 默认待办 | 在任务行或看板改状态 |
| 优先级 | 默认普通 | 星标或重要标记 |
| 计划日期 | 可以没有；今天入口只带入选定日期 | 今天 / 明天 / 本周 / 自选日期 |
| 截止日期 | 放在更多属性中，不等于计划日期 | 有明确交付要求时填写 |
| 计划开始 | 普通新增不要求；日历新增带入点击时间 | 点击时间标签或拖入日历 |
| 计划结束 | 不作为默认输入框 | 选 15/30/60 分钟，支持其他时长及精确结束时间 |
| 备注 | 初次隐藏 | 详情侧栏补充；需要时快速展开 |

减少的是初始可见字段和重复决策，不是删除已有信息。筛选入口带入的值必须可见、可清除；不应盲目沿用上一个任务的日期或项目。

### 建议的三种输入入口

1. **快速收集**：输入“整理项目报告”→ Enter→保存在收件箱，不强行排时间。
2. **快捷安排**：输入标题→点“明天”→可直接保存为明天待办；知道几点时再选“09:00”“30 分钟”。
3. **一句话录入**：拟支持“明天下午 3 点整理报告，45 分钟”。输入下方展示解析出的完整日期、15:00、45 分钟；可以点击修改或撤销识别。只识别有把握的中文句式，不明确的内容保持原标题。

第三种是拟议的 AgentValue 行为，不代表参考产品对这个中文例句已经支持。第一轮先做好前两种和规则识别；语音、跨应用快捷入口及 AI 解析之后再验证。

### 执行记录也要减负

- 开始 / 暂停 / 结束计时后，带入实际时间段；暂停间隙不算工作时间，连续多段执行分别保留。
- 结束时允许“保存记录”或“保存并完成”；结果说明可稍后补充，二者不互相强制。
- 补录提供“刚刚 30 分钟”“自选开始＋时长”，显示完整起止时间让用户核对；不是把今天计划时间自动当成已做。
- 单独写成果或备注也能保存，但未提供时间的记录不能进入耗时统计。
- 每日回顾自动带出已有记录和未完成任务，只补充遗漏内容，不重复要求写整份日志。

支持未分类、未计时备注、多次计划时间段和可恢复草稿，会涉及数据模型与持久存储；未来实现不能只折叠表单就宣布功能完成。

## 6. 前端展示怎么更完整、更好操作

### 入口与工具栏

保留清晰的“今天、事项、日历、回顾、资产”主模块。在事项下增加收件箱、近期、重要和项目等可选分组，常用分组可固定。日历入口持续直接可见，不藏进更多菜单。

统一任务工具栏为视图切换、筛选、排序、分组。第一批筛选只提供未完成/重要/项目/分类/未排期，避免一次塞入很多条件；常用条件可保存。快捷按钮保留文字，更多菜单使用明确动词。

### 任务行和详情

清单作为快速处理的默认候选：完成勾选、标题、日期/时间、预计时长、重要标记。点击日期直接改期；任务行提供开始计时与更多操作。备注、工具、执行历史和复杂属性放进详情侧栏，不必每张卡片全部展开。

支持选中多个事项统一安排日期、设置项目或改状态，操作后可撤销。键盘提供 Enter 连续录入、Esc 关闭、可发现的快捷键提示，并处理中文输入法确认文字时的 Enter，避免误提交。

### 可视化展示的分工

| 展示方式 | 用途 | 下一版优化 |
| --- | --- | --- |
| 当天日程列表 | 快速看接下来要做什么 | 按时间分组，全天/未定时间单独列；小计作为任务的简短附属记录 |
| 小时轴 / 周日历 | 分配与调整具体时间 | 任务列表同屏；拖入排期、拖动改时、拉边缘改时长；支持非拖动的菜单操作 |
| 看板 | 管理任务状态 | 折叠已完成与空列、卡片行内操作、批量改状态 |
| 项目时间线 | 看阶段、节点和截止要求 | 明确区分阶段跨度与单次工作时间；没有阶段跨度的事项显示节点，避免一律画成一天的甘特条 |
| 月历 | 看忙闲和重要日期 | 日格只显示摘要与数量，点击展开当天列表，避免把任务全文塞进格子 |
| 年度概览 | 看目标和里程碑 | 由目标关联任务计算进度，不用时长代替完成度 |

桌面优先采用“事项列表＋日历”的两栏布局，选中任务才打开详情侧栏。窄屏切换任务和日程，不强行挤成三栏。只有能直接操作的按钮才占据主要位置。

## 7. 分批落地与验证目标

以下按产品优先级分批，不是对工期的承诺。

| 批次 | 建议范围 | 验证方式 |
| --- | --- | --- |
| 第一轮，优先本周规划 | 标题快速新增、按需属性、日期与时长按钮、独立小计、行内改期、详情侧栏 | 普通新增只需输入标题；打开即能写小计；关闭草稿后可恢复；明确保存范围 |
| 第二轮，后续季度规划 | 任务日历联动、拖动与非拖动排期、批量操作、重复事项、个人模板、保存筛选 | 改计划不改截止日期；批量操作可撤销；模板不用逐项重填；实际记录不受改期影响 |
| 进一步研究 | 中文自然语言扩展、语音输入、外部日历、可选自动排期 | 覆盖歧义日期、跨午夜、识别撤销和纠正；确认你的主要输入习惯再设计 |

首轮设定可测目标：普通新建初始只显示一个文字输入区；从日历新增无需再次选择已经点击的日期与时间；有计时记录的小计无需手填起止时间；不记时也能完成事项。增加真实保存后，关闭或重启不能丢数据。

不能承诺“提升 50% 效率”或“10 秒完成所有新增”。后续以你真实的几个工作任务、生活提醒和阅读任务，比较完成一次操作的时间、点击数、输错次数与是否愿意持续使用。

- 当前产品：本轮三张截图、浏览器结构与焦点观察，另核查 `src/assistant/Workbench.tsx` 中表单、固定排期默认值、计时与小计流程。
- 缺失证据：AgentValue 多用户访谈、长期使用记录、商业产品真实操作、量化易用性对比、完整无障碍测试。本报告为下一版产品设计依据，不是上线验收。
