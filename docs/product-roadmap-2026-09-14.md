# AgentValue 优化与功能扩展分析

调研完成于 2026-09-14；参考仓库拉取于 2026-09-13。当前项目基线为 `67b62f623abb06c3ee1bc16140ed3e4e21e62126`。本报告依据本地源码与参考项目的选定源码，属于产品和静态实现分析；没有运行参考项目，也没有测量 AgentValue 的大库性能。下文的版本划分是建议，尚未实现。

**核心判断**

AgentValue 已经具备有价值的组合：Skill 独立收藏副本、文本 Prompt、图片 Prompt 和带正文快照的实验记录。继续发展的重点应是让这些资产更容易收集、找到、复用和分享，同时保留来源与使用结果。

最值得形成的特色是：一套任务所需的 Skill、Prompt、参考图和成功案例能一起保存、一起复用。建议先把个人使用闭环做好，再通过可选择内容的资产包支持协作者。在线生成、多模型调用和云端实时协作会引入另一组维护成本，可以在出现明确需求后评估。

**当前实现中最需要关注的六处问题**

| 已观察到的实现 | 对用户的影响或可能风险 | 建议 |
| --- | --- | --- |
| `exportBackup()` 提供完整导出，恢复仍依靠退出应用后手动复制 | 换电脑、误删恢复的门槛较高 | 增加校验、预览、恢复前备份和应用内恢复流程 |
| 数据库事务中会复制图片文件，回滚只撤销数据库操作 | 多图导入中途失败时，已写文件可能成为孤立文件 | 引入暂存、补偿清理及启动时恢复检查 |
| 删除记录保留文件，Skill 更新旧副本与 Git 缓存持续保留 | 占用随使用增长；文件保留也不等于记录可恢复 | 回收站保留记录关系，提供可预览的空间清理 |
| `state()` 每次加载全部正文、图片记录和实验，再用多层数组筛选组装；复制后也全量刷新 | 数据量增长时，查询、传输和渲染开销都会增加 | 列表摘要与详情分离，分页、局部更新与数据库搜索 |
| 列表直接使用原图；生成参数主要手填；单张图片管理不足 | 大图浏览开销大，整理和复现实验费时 | 缩略图、独立删除/排序/封面、元数据解析 |
| Skill 更新检查比较仓库 HEAD，与具体 Skill 子目录是否变化无关 | 仓库其他文件变化也可能出现更新提示 | 同时保留仓库提交与 Skill 目录哈希，按目录变化提示 |

**功能建议与取舍**

1. **变量模板与快速复用：优先级高，投入中。**

   例如保存「请以 `{{语言}}` 为 `{{目标用户}}` 撰写 `{{主题}}`」，使用时自动出现三个输入框，填写后预览并复制。支持默认值、必填项、枚举值及中文变量名；模板正文与一次使用时填写的值分开保存。优先采用可预测的变量替换，不执行模板内脚本。

   随后加入全局快捷键呼出的搜索小窗，回车复制，带变量的条目先填表。现有 Ctrl+K 只在应用窗口内有效。可以增加用户主动触发的“收集剪贴板内容”，先预览再保存。这能直接缩短日常操作路径。

   参考：[模板处理](https://github.com/linshenkx/prompt-optimizer/blob/1ee326fc891ea514744761a16b272408b29fb711/packages/core/src/services/template/processor.ts)、[快捷窗口](https://github.com/wbgcoding/Prompt-Saver/blob/a593f875295a882e7b32657396880a38156ac430/ui/launcher.js)、[变量窗口](https://github.com/wbgcoding/Prompt-Saver/blob/a593f875295a882e7b32657396880a38156ac430/ui/vars.js)。Prompt-Saver 的快捷窗口实际采用子串评分，不能直接视为具备拼写纠错的模糊搜索。

2. **图片整理与实验记录：优先级高，投入中到大。**

   先增加单张图片删除、拖动排序、指定封面、参考图与效果图角色修改，以及实验编辑/删除。历史正文快照继续保留；编辑实验备注不应悄悄改写原始生成输入。

   下一步导入图片时读取可用的 Prompt、负面 Prompt、模型、Seed、尺寸、采样器等参数。先支持一组明确的格式，例如 A1111 PNG 参数，再扩展到常见 ComfyUI 工作流。保留原始元数据、解析器版本与识别结果，解析失败时仍允许正常收藏。没有嵌入参数的图片不能自动恢复原始 Prompt。

   增加两个实验并排比较，并高亮参数差异。现有实验保存正文快照，但参考图关联在 Prompt 层；要支持可靠追溯，还应在实验中冻结实际使用的参考图版本或哈希。模型、Seed 相同也不保证跨环境完全复现，因此功能表述应是“保留实验条件”。

   参考：[元数据读取](https://github.com/RupertAvery/DiffusionToolkit/blob/153409c3a0e9569886e6601530365808d4ecbb0e/Diffusion.Scanner/Metadata.cs)、[参数结构](https://github.com/RupertAvery/DiffusionToolkit/blob/153409c3a0e9569886e6601530365808d4ecbb0e/Diffusion.Scanner/FileParameters.cs)。

3. **可恢复的数据与空间管理：基础优先级最高，投入中到大。**

   提供备份恢复向导，展示备份日期、格式版本、条目数量、缺失文件和校验结果。首版实现“恢复整个库”，操作前自动保留现有库；“导入部分条目”由资产包功能处理。引入顺序化数据库迁移，为以后新增字段与旧版本升级建立可靠路径。

   删除进入可恢复的回收站，保存数据库关系。清理功能分别统计回收站、Git 缓存、旧 Skill 副本与孤立图片，先展示可回收容量和影响，再执行清理。图片/Skill 导入采用暂存与操作记录，处理正常异常和程序意外中断。备份过程中还需要固定一致的数据视图，避免数据库与后续文件复制代表不同状态。

   本项直接来自当前实现的缺口，优先级高于增加更多资产类型。

4. **大库搜索与浏览：基础优先级高，投入中。**

   列表仅取标题、标签、封面和摘要，打开详情时才加载正文、文件树和实验；复制或收藏只更新受影响条目。图片采用原图、预览图、缩略图三级存储，内容哈希用于识别重复导入；需要区分“同一图片文件”和“同一图片在不同实验中的引用”，避免错误去重。

   搜索增加类型、多个标签、模型、评分、日期和有无参考图等条件，并覆盖实验备注、参数和历史快照。可以先提供筛选控件，再支持类似 `type:image tag:海报 rating:>=4` 的语法；这是拟议功能，并非当前已支持语法。

   数据库侧评估 FTS5 与索引，中文分词/子串检索需要独立验证，不能只开启默认全文索引便认为中文搜索已经解决。语义向量搜索可在真实检索失败案例积累后再评估。

   参考：[图片字段与全文索引](https://github.com/EddieTYP/image-prompt-library/blob/92fc666d670472b0b51806a0e61ff64fab6e34d3/backend/migrations/001_initial.sql)、[搜索条件解析](https://github.com/EddieTYP/image-prompt-library/blob/92fc666d670472b0b51806a0e61ff64fab6e34d3/backend/services/search_query.py)。

5. **选择性资产分享包：协作价值高，投入中到大。**

   你已经提出让另一位协作者完整使用项目。当前 GitHub 分发解决了程序与源码交付；每个人的收藏库仍然独立。下一步最实用的是勾选若干 Skill、Prompt、图片和实验，导出一个可移植的 `.agentvalue-pack`，协作者导入后直接使用。

   包内包含版本化清单、相对路径、来源、正文版本及文件哈希。导入前预览内容与冲突，提供跳过重复项、另存副本、选择更新；以稳定资产 ID 和版本关系识别冲突，不能仅按标题覆盖。压缩包读取需验证路径与体积，失败时保持原库完整。

   在此基础上增加“集合”：例如把“论文写作 Skill + 摘要模板 + 审稿模板 + 成功案例”组成一个可分享的任务包。它能把当前三个独立分类连接起来。整库备份继续服务灾难恢复；资产包服务有选择的交换。不要让多台电脑直接共同写同一个同步盘 SQLite 文件。

   参考：[收藏资产版本与选择性导出接口](https://github.com/linshenkx/prompt-optimizer/blob/1ee326fc891ea514744761a16b272408b29fb711/packages/core/src/services/favorite/types.ts#L146)。资产包格式与冲突策略属于对 AgentValue 的设计建议，不能直接视为该参考项目现成实现。

6. **Skill 来源与部署管理：优先级中高，投入中到大。**

   保留当前本地副本与外部修改保护，完善输入解析：仓库简写、分支/Tag、子目录地址。对同一仓库多个 Skill 复用一次拉取结果，以 Skill 子目录内容变化判断更新，并提供进度、取消和缓存清理。

   在“复制到项目”上增加部署记录：来源、版本、目标目录、安装时文件哈希。更新时展示变化，仅在目标文件仍与已安装版本一致时提供安全更新；有本地修改则保留并提示处理。首版支持少量常用工具目录模板和自定义路径即可。

   参考：[来源与目录哈希](https://github.com/vercel-labs/skills/blob/d667282815248da03a08a18272b5d2eef9caf77c/src/skill-lock.ts#L13)、[项目安装锁文件](https://github.com/vercel-labs/skills/blob/d667282815248da03a08a18272b5d2eef9caf77c/src/local-lock.ts)。

7. **文本 Prompt 版本与使用案例：优先级中，投入中。**

   保存重要修订版本，支持查看变化与恢复为新版本；记录一次使用的输入变量、模型、输出示例和评价。评价应关联具体任务与结果，例如“适合中文摘要压缩”，比给整段 Prompt 一个缺少上下文的通用分数更有用。

   先允许手动粘贴结果，不要求接入模型 API。这样能够与现有图片实验共享“模板—版本—使用记录”的结构，也为后续资产包提供完整上下文。

   参考：[收藏 Prompt 版本管理](https://github.com/linshenkx/prompt-optimizer/blob/1ee326fc891ea514744761a16b272408b29fb711/packages/core/src/services/prompt-model/favorite.ts)。

8. **批量整理与持续交付：优先级中，投入小到中。**

   增加多选、批量标签、标签重命名/合并、移动分类、导入预览和失败明细。数量超限时明确显示未纳入的文件，避免用户误以为全部保存。

   分发上先增加应用内查看版本和打开发布页，保留数据兼容检查；签名安装包与自动更新可作为后续独立事项。当前 Electron 架构能够支持上述扩展，暂时没有足够证据支持为了包体积重写为另一套桌面框架。

**建议实施顺序**

| 批次 | 核心交付 | 用户获得的结果 | 依赖与范围 |
| --- | --- | --- | --- |
| 第一批：可靠保存、顺手使用 | 恢复向导、迁移与导入补偿；图片独立管理和缩略图；基础变量模板 | 更敢存、更容易整理，模板直接填写使用 | 回收站与清理可拆成后续小版本；避免同时开发所有参数格式 |
| 第二批：快速查找、便于交换 | 分页与组合搜索；全局快捷窗；图片元数据首批格式；选择性资产包 | 大库查找更稳定，减少手填，协作者获得指定资产 | 资产包依赖稳定的数据版本和文件引用；元数据解析需格式样本 |
| 第三批：来源和使用追溯 | Skill 目录级更新与部署记录；文本版本、实验比较；任务集合 | 明确资产从哪里来、用在哪里、哪次效果好 | 先统一版本与使用记录结构，再扩展工具适配 |

投入等级是相对复杂度判断，不是工期承诺。若只选三个产品增量，我建议依次选择 **变量模板、图片参数导入、选择性资产包**；恢复与数据一致性作为这些功能的共同基础同步补齐。

**实现方式与验收依据**

现有 `App.tsx` 约两千行，应随功能改动拆出列表、详情、编辑表单和数据查询模块。存储层分离查询、图片导入、Skill 来源、备份恢复等服务；共享 IPC 输入结构与验证规则。耗时复制、哈希、图片处理和备份交给后台任务，提供进度与取消。维持现有桌面技术栈，逐步调整即可。

建议为各阶段定义可验证结果，以下均为拟定验收目标，非本轮测试成绩：

- 在空库恢复、已有库恢复、文件缺失、格式不兼容及中断场景下验证恢复流程；失败后原库仍可打开。
- 多图导入中途失败、程序在文件替换前后退出，重启后能够识别并恢复一致状态。
- 使用固定中文/英文查询集，在 1,000 和 10,000 条资产及不同图片规模下测量首次加载、查询延迟与内存，再设定机器明确的性能门槛。
- 图片元数据用真实格式样本验证字段映射；没有元数据、未知节点或损坏字段时不填造假结果。
- 相同资产包重复导入不会无提示地产生重复项；冲突处理不会覆盖未选择更新的内容。
- Skill 仓库无关目录变化不提示该 Skill 更新；目标存在本地修改时不被覆盖。
- 变量替换验证中文名、重复变量、空值、转义及取消操作；全局快捷窗支持完整键盘操作。

暂缓云账号与实时协作、在线生成、Agent 编排、MCP 服务端和默认语义向量检索。它们可以成为以后独立评估的方向；近期路线的衡量标准是资产保存是否可靠、找到并复用是否更快，以及分享时能否保留完整上下文。
